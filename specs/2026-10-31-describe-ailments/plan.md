# Plan: Describe ailments

## 1. Define ailment data

1. Define a TypeScript type for an ailment, with fields needed to identify and describe it.
2. Choose a stable way to associate an ailment with an agent.
3. Add one fictional ailment to the local data for an agent.
4. Keep the data local and separate from presentation where that matches the existing project structure.

## 2. Present ailments on agent details

1. Show the ailment name on the associated agent detail view.
2. Show its short description in clear, readable language.
3. Use the agreed empty state when an agent has no listed ailments.
4. Keep the view semantic, keyboard accessible, and responsive.

## 3. Validate and hand off

1. Confirm the fictional ailment appears on the correct agent detail view.
2. Confirm agents without ailments show the agreed empty state.
3. Check keyboard access and narrow/wide layouts.
4. Run the project build and record the command and result in the implementation handoff.
