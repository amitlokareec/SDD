# Plan: Prepare for real use

## 1. Choose the staff sign-in approach

1. Choose and document how staff sign in.
2. Record the approach and rationale in `specs/tech-stack.md` before implementation depends on it.
3. Document required configuration and local setup.

## 2. Protect staff actions

1. Protect one staff-only action using the selected sign-in approach.
2. Add visible sign-in and sign-out paths.
3. Give signed-out users clear feedback when they reach a protected action.

## 3. Review usability and browser support

1. Review the agent list with a keyboard.
2. Review booking form labels and error messages.
3. Check responsive layout in current major browsers.

## 4. Document build and release

1. Document local setup and required configuration.
2. Document how to build and release the app.
3. Keep instructions consistent with the selected server, database, and sign-in setup.

## 5. Validate and hand off

1. Check signed-in and signed-out access, sign-in/out paths, and the protected action.
2. Complete the keyboard, form, and browser review.
3. Follow the documented build and release steps and record results in the implementation handoff.
